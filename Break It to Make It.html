Security session
Break It to Make It
Making a pizza website as insecure as possible, on purpose.
Today's rules
The worse the idea, the better
Be terrible
We're trying to break things, not build them properly.
Use everyday words
No coding knowledge needed. Describe it like you'd tell a friend.
No wrong answers
Every idea counts, however silly. Silly is often where the good ones are.
Your target
Meet Crust Club, a small pizza takeaway's website
Customers
Create an account, save their address and card, order pizza, and see past orders.
Staff
Use a separate admin page to see orders, change prices, and issue refunds.
The website
Built with lots of free code written by other people, and hosted in the cloud.
When something breaks
The site shows an error message to whoever is using it.
How software gets made
Things can go wrong at every stage, not just in the code
1
Plan
Nobody asks how it could be misused
2
Design
Refunds of any amount, no checks
3
Build
Borrowed code with holes, passwords in the code
4
Test
Only testing when things go right
5
Release
Default settings left on, updates not checked
6
Run
Nobody watching for anything odd
And at every stage: people. Shared logins, phishing emails, and laptops left unlocked.
Packages and tools
We don't build everything ourselves
What's inside Crust Club
Packages
Free code written by other people, for logins, payments, web pages and more
Our own code
Often, most of an app is code we didn't write
How it reaches customers
Write the code in an editor
Store it somewhere shared, like GitHub
Build it with tools that download the packages and bundle everything up
Deploy it automatically to a cloud server
Every package and every tool is something we trust. If one of them is broken or tampered with, so is Crust Club.
Step 1 · 15 minutes
Make Crust Club as insecure as you possibly can
1
On your own
2 min. One terrible idea per sticky note.
2

3 min. Share, then make them even worse.
4

All
Whole room
5 min. Each table shares its single worst idea.
Stuck? Go through the stages: plan, design, build, test, release, run. Then think about the packages, the tools, and the people.

Steps 3 and 4 · 18 minutes
Be honest, then fix it
3 · BE HONEST
Which of these could someone do by accident?
Put a dot on every sticky note that could happen without anyone meaning to. Which ones might you do in your first few months?
4 · FIX IT
Turn your top three into simple rules
"The admin password is pizza" becomes "Use strong, unique passwords and a second login step for staff."
